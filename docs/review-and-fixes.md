# 独立代码审阅与修复

独立审阅在初版实现后发现七项需要补强的问题，均先用回归验证复现，再修改实现。最初审阅属于开源导入前的本地历史；本文记录最终处理方式，不将初次审阅当作修复后的独立批准。

| 问题 | 修复与证据 |
| --- | --- |
| 固定提交工作区残留未跟踪输入 | 重置后清理声明生成路径，拒绝其余未跟踪/未知忽略输入，核对受控文件；`test_reused_snapshot_rejects_untracked_execution_inputs` |
| Unity 互相矛盾的报告仍能准入 | 完整对齐任务、目标、配置、引擎和资源摘要，要求 Player、bundle 与嵌入信息；`test_unity_admission_binds_complete_receipt_and_expected_payload` 六项反例 |
| API 非法类型导致 500 或污染节点登记 | 严格请求模式、字段类型与范围，持久层继续校验；四项非法请求回归 |
| 一次构建失败终止常驻节点 | 单次模式保留失败返回码，常驻模式记录失败并继续；真实 HTTP 进程先处理坏任务再成功处理下一任务 |
| 两次布尔批准代替发布验证 | 观察绑定制品摘要、真实节点、验证 ID 与运行回执；每阶段要求两个不同节点及至少一秒窗口，失败记录入账并拒绝晋级 |
| CLI 等待中断未取消远端任务 | 超时、异常与 SIGTERM/KeyboardInterrupt 路径尝试撤销任务；超时回归核对服务端 cancelled |
| 单包成功错误推断双分支并行 | A04 只读取真实双分支并行报告，核对时间重叠与独立源码/工作区/Library/输出；独立汇总回归 |

另收紧 Windows 制品路径，拒绝设备名、尾随点空格及大小写变体的禁入路径；显式关闭数据库读连接；清理生成资源后再计算静态检查缓存键。源码与流水线在这些修复后重新冻结并运行验证，公开版应以当前 `python -m pytest -q` 输出为准。

本版本的 HTTP 上传在 multipart 解析后对制品副本实施大小限制，部署边界为本机回环地址、单个受信任工程和认证节点。没有宣称具有公网多租户入口所需的前置代理接收限额或执行沙箱。

范围边界：同机逻辑节点不等于跨主机，Docker 不等于 systemd/k3s。旧企业业务源码及其平台修复实验不在公开版中。其余边界见 README 与架构文档。
